Every turn re-sends the whole thread to the model: your messages, the agent's answers, and every tool result. The context window is finite, so a long thread runs out of room eventually. Input gets truncated, and Shape seems to forget what you said an hour ago.

A short chat never hits the limit. A long one does, and it helps to know what survives.

## What happens, in order

1. **Tool output is trimmed.** Old tool results shrink to a head-and-tail excerpt. A result the model no longer needs, such as an older read of a file it read again later, becomes a one-line note.
2. **Older turns are summarized.** Past roughly 74% of the window, Shape folds the older turns into one summary and keeps the newest turns word for word. That is compaction.
3. **The summary is reused.** After the first fold, later turns send the summary plus the recent turns instead of the whole transcript, so Shape does not re-summarize on every message.
4. **Oversized output goes to disk.** A single tool result too big for the budget is written under `.shape/agent-out/` and the model gets the path.

## Run it yourself

```
/compact
/compact keep the migration plan and the API shapes
```

Manual compaction uses the same engine as the automatic pass, so a thread you compacted by hand keeps working the same way. The agent can also compact mid-task when a turn is running long.

## What the summary keeps

The summary follows a fixed outline rather than a free-form recap:

- The request and the intent, including anything you ruled out.
- Technical concepts and the shape of the solution.
- Files and code sections, with the important snippets.
- Errors, fixes, and rejected approaches.
- Problems solved and the state of the work.
- Every user message, so early instructions survive.
- Work in progress and the next step.

Shape also re-attaches the five most recently read or written files, so the agent picks up where it left off instead of re-reading them.

Want every summary to carry something specific? An API shape, a set of migration names, a house tone? Write it once in Settings → Agents → Instructions → Compaction. Those instructions are appended to every compaction, manual or automatic.

## When the agent slows compaction down

Automatic compaction picks its moment from a token count, and a token count cannot tell whether the agent is half-way through a rename across six files. When it is, the agent can hold the automatic pass. It does that on its own, with a one-line reason:

```json
{ "action": "defer", "reason": "half-way through the rename across six files" }
```

That call is the hold, not a summary of the work. The reason is pinned into the next summary, so the thing it was protecting survives the fold.

A hold is bounded, because an unbounded one would let the window overflow, and a truncated window loses more than a summary does:

- It lapses after about 15 minutes, or 16k tokens of growth, or 3 skipped passes.
- It is overridden when the chat reaches about 92% of the window.
- `/compact` from you always works, and a finished turn clears the hold.

Settings → Agents → Context shows the hold, its reason, and a **Compact now** button while one is active.

## What you still see

Compaction changes what the model reads, not what you keep. The earlier messages stay in the chat, with a marker where the summary took over. The pre-compaction transcript is archived under `.shape/agent-out/`, so the agent can grep it when a detail is missing.

Each chat keeps its own summary. Opening another thread, or starting a new one, starts from that thread's history.

Settings → Agents → Context shows what compaction has done in the open chat: how many passes, how many tokens it freed. Reset goes back to sending the raw transcript, and since nothing was deleted, nothing is lost.

## When compaction does not run

- Incognito chats are never summarized.
- If the summary call fails, or the result is too short to be useful, Shape leaves the thread alone and retries later. It will not silently drop turns.
- "Nothing to compact yet" means the thread is still small enough to send whole.
