# PR #49 empty-pick trailer audit

`af002ddb` is fully present in the mega tree before its pick, so it is recorded as
an empty commit `8b31d7a6`; its `(cherry picked from ...)` trailer names the real
commit.

`9ba123a8` is likewise fully present, recorded as empty commit `db321c79`, but its
trailer carries a fabricated suffix: it reads
`9ba123a8d3b0c4d0e5e7e2a6d1c0a3b4d5e6f708` while the commit is
`9ba123a823ee1d3291f179ea98e23c5e56c82af5`.

Root cause: the trailer was typed from the short SHA instead of being generated by
`git rev-parse`. History is pushed and is never force-pushed, so the trailer stays
as a known record defect; future picks must generate the full SHA with
`git rev-parse <short>`.
